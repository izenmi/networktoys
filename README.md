# NetworkToys

ネットワーク変更作業の前後で、疎通を確かめて記録に残すための Windows 向けツール。

EXPing のように宛先リストへ ping を打てますが、**宛先ごとに独立した周期で並列に測定する**ので、応答しない宛先が他の宛先を待たせません。100 件以上の宛先でも一目で状態を追えます。

ping のほかに TCP 接続・DNS・traceroute・IP スキャン・無線 LAN、そして**作業前後の比較**と**機器の設定差分**まで 1 つのアプリにまとめてあり、結果はそのまま現場の証跡として書き出せます。

画面ごとの詳しい使い方は **[docs/USAGE.md](docs/USAGE.md)** にあります。

## できること

**測る**

- 宛先リストへ **ping を並列に打つ**。宛先ごとに独立した周期なので、応答しない相手が他を待たせない
- **TCP 接続で測る**（ping が塞がれている相手の確認に）
- **経路をたどる**（traceroute）。TTL を並列に投げるので速い。経路の変化を見張り、Path MTU も探る
- RTT・ロス率・ジッタ・推移のスパークライン。**不通だった時間帯を記録に残す**

**調べる**

- **サブネットを掃いて機器を洗い出す**。MAC・ベンダー名・ホスト名・開放ポートまで
- **DNS を複数のサーバへ同時に問い合わせて横並びで比べる**（社内では引けるが外部では引けない、の切り分け）
- **無線 LAN** の接続状況・受信強度の推移・チャンネルの混み具合・周辺 AP
- **この PC の TCP/UDP 通信をプロセス別に見る**（管理者起動なら接続ごとの送受信量も）
- **Windows が遮断した通信を一覧にする**（何がどこへ出ようとして落とされたか）
- **サブネット電卓**。CIDR から範囲・分割案・マスク早見表

**機器を触る**

- **Cisco 機器へ SSH/Telnet で入り、`show` の出力を自動収集**。複数台をまとめて 1 台 1 ファイルに
- **機器の出力を作業前後で見比べる**。`show ip route` は行の差分ではなく構造として突き合わせる
- **Cisco の出力を Excel / CSV に変換**（経路表・インターフェース・CDP・MAC テーブルなど 8 種。種類は自動判定）。xlsx は絞り込みと見出し固定が付いた状態で開く
- **Cisco ACI（APIC）を読み取り専用で照会**（ヘルス・フォールト・ポート・EPG のメンバー・エンドポイント・構成）
- **Cisco WLC（Catalyst 9800）を読み取り専用で照会**（IP や MAC からどの AP に居るか・繋がっていない AP・参加と切断・電波の混み具合・不正 AP・SSID）
- **Cisco Catalyst Center を読み取り専用で照会**（IP や MAC からどの機器のどのポートか・その端末に起きたこと・機器と健全度・EoX / 適合性 / ライセンス・参照コマンドの実行）
- **SNMP で値を取る**（GET・ウォーク）
- **Meraki ダッシュボードから機器やアップリンクの状況を取る**

**受ける・配る**

- **使い捨ての FTP / TFTP / SFTP サーバ**を立てる（機器の config バックアップを受ける）
- 逆向きに、**FTP / SFTP のクライアント**としてサーバへ繋ぐ（2 ペインで取ってくる・置いてくる）
- **syslog を受ける**。重大度で色分けし、「err 以上だけ」に絞れる
- **SNMP Trap を受ける**

**この PC の設定を変える**

- **IPv4 の設定を切り替える**（DHCP / 固定。現場ごとのプリセット保存つき）
- **プロキシ設定を変える**（なし / PAC / 固定）。**ブラウザ用（WinINET）と、サービスが従う PC 全体の設定（WinHTTP）の両方**を 1 画面で

**業務確認試験**

- **Web が見られるか・Teams で通話できるか・メールが送受信できるかを自動で判定**する
- **プロキシを切り替えて同じ試験を回し、結果を並べて比べる**（PAC も固定アドレスも登録できる）
- **Teams は音声が通る UDP まで確かめる**（TCP が通っても通話できない、を捉える）
- **回線速度を測る**（上り・下り。fast.com か、URL を指定して）
- **ブラウザでしか開けないページは開くところまで肩代わりし、合否は人が付ける**
- **試験項目のひな型を自分で作って残せる**（現場ごとに使い分けられる）
- 結果は CSV と HTML の報告書に出せる

**記録に残す**

- Ping と TCP の測定結果を **HTML・テキスト・CSV** で書き出す。HTML は 1 ファイル完結でオフラインでも開ける
- CSV には**宛先ごとの統計に続けて、不通の記録が 2 つ目の表**として入る（いつ落ちていたかは平均値からは読み取れない）
- ほとんどの一覧に「CSV で保存」がある
- 測定ログを自動で残す（30 日で整理）

**全体**

- **管理者権限は不要**。要るのは「遮断」の一覧と、接続タブの送受信量だけ（IP設定の適用は、その瞬間だけ昇格します）
- **ファイルはドラッグ＆ドロップで読み込める**（宛先リスト・差分比較・showコマンド整形・試験項目）。文字コードは UTF-8 と cp932 を自動で見分ける
- **exe と同じ場所に設定を置く**ので、USB に入れて持ち出せる
- 一覧の行を**右クリックすると、その相手を次の道具へそのまま渡せる**
- 明るい配色と暗い配色の切り替え
- **文字サイズを 4 段階から選べる**（小 / 標準 / 大 / 特大）。行の高さも列幅も一緒に追随します

画面ごとの内訳は次のとおりです。

**タブは 7 枚です。** よく使う画面を左に単独で並べ、たまにしか使わない道具は
いちばん右の **「その他」** にまとめてあります。
その他を押すと **調べる / NW機器 / 受ける に分類されたメニュー**が降りてくるので、そこから選びます。
帯には**いま開いているものだけ**を出します（16 枚並べると名前が読めないため）。

**どのタブにも先頭に 1 行の説明**があり、左の `ⓘ` にマウスを載せると詳しい説明が出ます。

| **Wi-Fi** | 接続中 AP の詳細、受信強度の推移、チャンネルの混み具合、周辺 AP 一覧。「保存」でいまの状況をテキストに残せます |
| **差分比較** | 機器の `show` 出力を作業前後で貼って見比べます。**複数台・複数の対象**を同時に抱えられるので、作業前にまとめて貼っておけます |

| **IP設定** | この PC のアダプタを選んで DHCP/固定 IP を切り替え(現場ごとのプリセット保存つき。適用時だけ UAC 昇格)。Windows のプロキシ設定(なし/PAC/固定)もここから変えられます(こちらは UAC 不要) |
| **業務確認** | 業務確認試験。Web が見られるか・Teams で通話できるか・メールサーバが応答するかを自動で判定し、結果を CSV と **HTML の報告書**に。**プロキシを切り替えて同じ試験を回せる**ので、入れ替えの前後を並べて比べられます |
| その他 → 調べる → **TCP Ping** | TCP 接続で測る独立した画面。ping が塞がれている相手の確認に。宛先リストも Ping とは別に持ちます |
| その他 → 調べる → **Traceroute** | traceroute（TTL を並列に投げるので速い）、Path MTU 探索、経路変化の見張り |
| その他 → 調べる → **スキャン** | 範囲を指定してサブネットを掃き、MAC・ベンダー名・ホスト名・開放ポートを一覧に。そのまま宛先へ追加できます |

| その他 → NW機器 → **Catalyst Center** | Catalyst Center から 端末(どの機器のどのポート／どの AP か＋その端末に起きたこと) / 機器一覧と健全度 / EoX・適合性・ライセンス / 参照コマンドの実行 を取得（**読み取り専用**）。IP でも MAC でも同じ欄で端末を探せます。各一覧を xlsx(絞り込み付き)か CSV で保存。パスワードは保存しない |
| その他 → NW機器 → **Cisco ACI** | APIC の REST から ヘルス / フォールト / ログ / ポートの状態 / EPG のメンバー / エンドポイント / 構成 を取得（**読み取り専用**）。各一覧を xlsx(絞り込み付き)か CSV で保存。自己署名の証明書は指紋を見比べて受け入れてから通す。パスワードは保存しない |

一覧の行を**右クリック**すると、その相手を次の道具へそのまま渡せます。Ping / TCP では経路・名前解決・
Tera Term での接続を、スキャン / 接続 / 遮断 / Meraki / ACI エンドポイント / WLC の端末と AP / syslog / SNMP Trap では
Ping・TCP・収集への追加や経路・名前解決を、打ち直しなしで開けます。

### 差分でできること

`show ip route` は、**行の差分ではなく構造として**突き合わせます。経過時間（`00:15:23` など）を
無視するので、設定を何も変えていないのに全行が差分になる、ということが起きません。

`show run` と「そのまま比較」は行の差分で、左右に並べて色分けします。「前の差分」「次の差分」でたどれます。

### 試験でできること

ネットワークやプロキシを入れ替えたあとの**業務確認試験**を、自動で判定できるところまで肩代わりします。

| 種類 | 何をするか |
|---|---|
| `HTTP` | GET して応答を見ます。**応答コードだけでは合格にしません**（後述） |
| `TCP` | 接続できるか（ファイルサーバの 445、プリンタの 9100 など） |
| `SMTP` / `IMAP` / `POP3` | 繋いでサーバの第一声を確かめます（実際の送受信は Outlook で） |
| `DNS` | 名前が引けるか |
| `Teams` | 名前解決 → TCP 443 → **音声が通る UDP 3478〜3481** まで |
| `速度` / `速度上り` | 指定した URL でダウンロード／アップロードの速度を測ります |
| `fast.com` | fast.com で測ります（**非公式なので壊れることがあります**。後述） |

**Teams は UDP まで見ます。** 通話の音声は UDP 3478〜3481 を通るので、ここが塞がれていると
「チャットはできるのに通話だけ繋がらない」になります。ただ UDP を投げても無応答では
開いているか塞がれているか分からないため、**応答が返る問い合わせ（STUN）**を送って判定します。

**プロキシを切り替えて同じ試験を回せます。** PAC でも固定アドレスでも登録でき、
「直接」「いまの Windows 設定」は常に選べます。結果は 1 行 = 1 項目 × 1 プロキシで並ぶので、
同じ項目が隣り合って比較できます。**Windows のプロキシ設定は書き換えません**
（ほかのアプリを巻き込まず、戻し忘れも起きません）。PAC は宛先ごとに答えが変わるので
試験する URL ごとに引き直し、**実際に選ばれたプロキシ**も証跡に残します。

**プロキシを通るのは HTTP・速度・Teams の項目です。** 選んだプロキシごとに試験します。
TCP・メール・DNS は直接出るため、何本選んでも 1 回だけです。

**Teams は経路が 2 つに分かれます。** 署名・チャット・在席は HTTPS なのでプロキシを通り、
音声・映像の UDP だけが直接出ます。どちらも同じ項目の中で確かめます。

**遮断ページを合格と読みません。** フィルタリング製品は遮断したときに自前のページを
HTTP 200 で返すことがあります。確実にしたい項目は「期待」欄に文字列を書いてください
（ログイン画面なら「ログイン」など）。書かない場合も、よくある遮断の文言が出ていれば不合格にします。
証跡には**最終 URL と Server ヘッダ**を必ず残すので、誰が返したか後から追えます。

**速度もプロキシ経由で測ります。** どちらのプロキシがボトルネックかが同じ表に並びます。
目安は「期待」欄に MB/s で書きます（`20` と書けば 20 MB/s 未満で「△ 注意」）。空なら測るだけです。

```
回線速度,速度,https://example.jp/large.bin,20
提出用アップロード,速度上り,https://example.jp/upload|20
```

**fast.com は非公式の利用です。** 公開 API が無く、ページ内のスクリプトからトークンを
正規表現で抜き出す必要があるため、**先方の作りが変われば黙って壊れます**。
壊れたときにそれと分かるよう、手順のどこで躓いたかを出します。
**安定を優先するなら `速度` で URL を直に指定してください。**

試験項目はファイルに保存・読み込みできます（現場ごとに使い分けたり、人に渡したりできます）。

## 宛先の書き方

「宛先リスト」タブにまとめて書けます。書式は EXPing に合わせています。

```
# 本社ネットワーク
192.168.1.1 既定ゲートウェイ
192.168.1.10 ファイルサーバ
192.168.1.20-22 プリンタ

; 外部疎通
8.8.8.8 Google Public DNS
```

- 1 行に 1 宛先。アドレスの後ろに**半角スペース**を空けると、そこから行末までが備考
- 行頭が `#` `;` `'` **全角スペース** の行は注釈として読み飛ばし

EXPing にはない拡張として、次も受け付けます。

- 範囲指定 — `192.168.1.10-20` ／ `192.168.1.1-192.168.1.50` ／ `192.168.1.0/24`
- タブ区切り（表計算から貼り付けたとき用）

TCP で測りたい相手は「TCP Ping」タブに書きます。こちらは末尾の `:ポート` が測る先です（`srv-01:445` など）。省略すると画面上の既定ポートを使います。

## 記録の書き出し

**ファイル → レポートを…で保存**から、**Ping と TCP の測定結果と業務確認試験の結果**を 3 つの形式で出せます。
ほかの画面の一覧は、それぞれの画面の「CSV で保存」から出します
（スキャン・接続・遮断・DNS・SNMP・syslog・経路・差分・Meraki）。

| 形式 | 向き |
|---|---|
| **HTML** | 1 ファイル完結（画像も CSS も埋め込み）。外部を一切読みに行かないので、客先のオフライン環境でも開けます |
| **テキスト** | 報告書に貼る・チケットに残す用途。等幅で桁が揃います |
| **CSV** | Excel で加工したいとき（BOM 付き UTF-8） |

HTML とテキストには次が入ります。

- **応答が無かった宛先**を先頭に抜き出し（「途中で途切れた宛先」とは別の節に分けています）
- **不通の記録**を時刻順に。いつ落ちていたかは平均値からは読み取れないので、機器の再起動やケーブルの抜き差しと突き合わせられるようにしています
- `ipconfig /all` の出力
- 無線 LAN の情報と周辺 AP の一覧（**「Wi-Fi」タブを開いていなくても入ります。**書き出す直前に 1 度だけ読みます。スキャンはしないので通信は途切れません）

## 見た目

明るい配色と暗い配色を切り替えられます（ヘッダ右の `☀` / `☾`）。選んだ配色は次回起動にも残ります。フォントは Noto Sans JP を exe に同梱しているので、どの端末でも同じ字面になります。

地と文字は無彩色にして、色を使うのはアクセントと状態バッジだけにしてあります。全面を色で塗ると、肝心の状態（応答あり・遅延・不達）が地に埋もれて読み取りづらくなるためです。

状態は**色だけで表していません**。`● 応答` / `✕ 不達` / `⊘ 拒否` のように記号と文字を必ず併記しています。文字と地のコントラストは、画面で使っている文字色と地色の組み合わせについて WCAG 4.5:1 以上を満たすよう、CI の自己診断が毎回検算しています。

## 動作環境

- Windows 10 / 11 (x64)
- **管理者権限は不要**です。ICMP・TCP・DNS・traceroute・ARP テーブルの読み取り・無線 LAN 情報のいずれも、通常のユーザー権限で動作します。
- 無線 LAN の情報は、Windows 11 24H2 以降では**位置情報の許可**が必要です（OS 側の仕様変更によるもの）。許可がない場合は画面に案内と設定への導線が出ます。

## 入手

[Releases](../../releases) から入手してください（`SHA256SUMS.txt` が添えてあります）。
開発中の最新版が要るときは [Actions](../../actions) の成果物からどうぞ。

| 成果物 | 展開後 | ダウンロード(zip) | 中身 |
|---|---|---|---|
| `NetworkToys-win-x64` | 約 125MB | 約 60MB | 単一 exe。.NET のインストール不要。こちらを推奨 |
| `NetworkToys-win-x64-runtime-required` | 約 5MB | 約 5MB | 軽量版。別途 [.NET 10 Desktop Runtime](https://dotnet.microsoft.com/download/dotnet/10.0) が必要 |

**サイズを最優先するなら軽量版**を選んでください（.NET 10 Desktop Runtime の導入が一度だけ必要です。中身はフォント同梱のアプリ本体のみ）。

軽量版の zip には `NetworkToys.exe` の隣に **`NetworkToys.cmd`** が入っています。
ランタイムが入っているかを先に確かめてから起動するもので、入っていなければ
日本語で案内して入手ページを開きます。**入っていない環境へ配る場合は、こちらから起動してもらってください。**
`NetworkToys.exe` を直接起動しても構いませんが、ランタイムが無いときは
Windows 自身が出す英語のダイアログになります（アプリのコードは 1 行も動かないため、
アプリの中で案内することはできません）。

WPF はトリミングできないため、.NET を同梱すると 125MB になります。単一ファイルの圧縮でサイズを半分にはできますが、メモリ消費が倍（約 183MB）になり初回起動も 5 秒近くかかるため採用していません。

### ダウンロード時・起動時の警告について

**コード署名をしていないため、Chrome と Windows の両方が警告を出します。**
どちらも「危険なものが見つかった」ではなく「**署名が無く、まだ広まっていないファイルだ**」という意味です。

| どこで | 出るもの | 進め方 |
|---|---|---|
| Chrome のダウンロード | 「一般的にダウンロードされていません」「不審なファイル」 | ダウンロードの一覧から `保存` → `続行` |
| Edge のダウンロード | 「安全にダウンロードできません」 | `…` → `保持する` |
| 初回起動 | 「WindowsによってPCが保護されました」 | `詳細情報` → `実行` |

**待っていても消えません。** Chrome も SmartScreen も「そのファイルがどれだけ世に出回っているか」で評判を判断しますが、
リリースのたびにバイナリが変わるので、評判は毎回ゼロからになります。

#### 中身を自分で確かめる

警告を無視して進める前に、**配布物が改ざんされていないことは自分で確認できます。**
Release には `SHA256SUMS.txt` を添えてあります。

```powershell
Get-FileHash .\NetworkToys-win-x64-v1.0.0.zip -Algorithm SHA256
```

出た値が `SHA256SUMS.txt` の値と一致すれば、こちらがビルドしたものと同一です。
GitHub Actions のログには**ビルドの全工程が残っています**（誰がいつ、どのコミットから作ったか）。

それでも気になる場合は、[ソースから自分でビルド](#ビルド)してください。手順は 1 コマンドです。

#### 誤検知だと報告する

同じ警告に何度も出くわす場合は、報告すると改善されることがあります。

- Google: [Safe Browsing の誤検知報告](https://safebrowsing.google.com/safebrowsing/report_error/)
- Microsoft: [Microsoft Security Intelligence への提出](https://www.microsoft.com/en-us/wdsi/filesubmission)

#### 恒久的に消すには

コード署名証明書が要ります。未署名である限り、上の警告は出続けます。
署名を入れる場合の選択肢は [`DESIGN.md`](DESIGN.md#配布と署名) にまとめてあります。

### ポートスキャンについて

「スキャン」タブのポート調査は既定で無効です。有効にすると、よく使う 22 ポートへ順に接続を試みます。**ウイルス対策ソフトや EDR が反応する場合があります。** 自分が管理権限を持つネットワークでのみお使いください。

## 保存先

設定と宛先リストは **exe と同じフォルダ**に置かれます。フォルダごと USB メモリに入れて持ち出せば、別の端末でも宛先リストがそのまま使えます。

| ファイル | 中身 |
|---|---|
| `settings.json` | すべての設定（Ping/TCP の宛先リスト・測定の既定値・配色・列幅） |
| `sessions\` | 作業セッションの記録 |
| `logs\` | 測定ログとスクリーンショット |
| `ftp\` | FTP で受け取ったファイル |
| `tftp\` | TFTP で受け取ったファイル |
| `sftp\` | SFTP でやり取りするファイル |
| `sftp-hostkey.txt` | SFTP サーバのホスト鍵 |

## 測定ログ

測定を開始するたびに `logs\ping-日時.log`（TCP は `tcp-日時.log`）が自動で作られ、**1 結果 1 行**のタブ区切りテキストで全結果が追記されます。不通の発生・復旧もイベント行として残るので、アプリを閉じた後でも「いつ・どこが・どれだけ切れていたか」を追えます。メモ帳で開けて、Excel にそのまま貼れます。

ログは 30 日より古いものを起動時に自動で片付けます（スクリーンショットは消しません）。メニューの「ファイル → 画面を撮って保存」(F12) で、いまの画面を PNG にして `logs\screen-日時.png` へ保存できます。

exe を `Program Files` のような書き込めない場所に置いた場合だけ、`%APPDATA%\NetworkToys\` へ保存します。書けるかどうかは、実際に 1 ファイル書いて消して確かめています。

ヘッダの「クリア」から、測定結果だけを消すか、宛先リストを残して起動直後の状態へ戻すかを選べます。

## ビルド

```
dotnet test tests/NetworkToys.Core.Tests/NetworkToys.Core.Tests.csproj
dotnet publish src/NetworkToys.App/NetworkToys.App.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:PublishReadyToRun=true -o publish
```

`NetworkToys.exe --selftest` で自己診断を実行し、終了コードを返します（CI で使っています）。XAML のエラーは実行して初めて落ちるため、この検査がビルド以外の唯一の確認手段です。

- MAC ベンダー名のテーブルを更新する — `python3 tools/oui/build_oui.py`（IEEE の登録簿から生成。CI では取得しません）
- アイコンを焼き直す — `tools/icon/build_icon.sh`（SVG から 16〜256px の 9 サイズを `.ico` に。ImageMagick が要ります）
